## Goal

The Next template reads like its three siblings. After this plan:

- the catalog ships `v1.12.0` with `frontend/next` 4.0.0: `app/` as the pages layer with
  route-private `_components/`, then `components/`, `services/`, `actions/`, `store/`, `models/`,
  `shared/`, `core/` and `styles/`; a sibling `.scss` beside every page and component over React's
  global tree; no Tailwind, no shadcn;
- the harness pins it, and its wording names no Feature-Sliced layer and no utility class;
- a list and form task on a bootstrapped Next project lands in the new homes unaided (P3).

## Risks

- **Stylesheet order under Turbopack** differs between a hard load and a client navigation, or
  between server and client components. Mitigation: S5 proves the eight cases before any move;
  the layers make the global tree lose at any order; a failure stops the plan.
- **The port restyles every screen at once.** Mitigation: `screens.spec` checks each screen in
  both themes on both viewports (axe, overflow, one `h1`); the session reads the captures.
- **A server-coupled or auth-coupled file is missed in `onlyWhen`.** Mitigation: the `alone` and
  `auth-off` cases' `check`, and the `SERVER_*` net of ADR 0011.
- **The tools constant changes React's or Vue's output.** Mitigation: C1's tree diff.
- **Co-located tests reach the image or the route table.** Mitigation: `.dockerignore`; Next
  routes only its named files; the `stack-postgres` case builds the image.
- **Word budgets.** Mitigation: replacements only; `docs.test.mjs` after each edit.

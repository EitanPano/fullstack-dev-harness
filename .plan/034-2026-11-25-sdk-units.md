## Goal

A project adds an SDK module as a short declaration and a frame half, and gets from the base:
inline and modal display, a public `mount` and `open`, its own events on the host page, a
stylesheet with breakpoints, and a dev loop that plans and judges the unit from screenshots.
The base holds no niche code. After this plan:

- the kernel owns the iframe, the handshake and the relays; a module's host half is data;
- the host page mounts a unit by a call or by markup, and hears `<module>:<event>`;
- one data path each way between page and frame: `props` in, `emit` out;
- the frame has a stylesheet, images by one server setting, and forms;
- telemetry is the frame's alone and each server has its endpoint and a sink to replace;
- the key resolver is asynchronous and a key can be switched off alone;
- a plan carries a `UX` line per unit, and the frontend agent and QA judge its screenshots.

## Assumptions

- `sdk/browser` 1.0.0 and the three server minors are on `dev` and untagged (newest tag
  `v1.17.0`), so the module contract, the public API and the loader-frame protocol change with
  no major and no migration. The proof project of plan 033 is disposable.
- "Unit" stays the word for one mounted instance of a module; instruction text says "SDK unit"
  where "unit tests" is near.
- A module needs no code on the host page. A host hook is an optional field later, a minor.
- Watching the page for slots added later is opt-in: a guest adds nothing standing unasked.
- A slot is mounted only for a module that declares it, with only the attributes it lists, and
  never as a modal: a sanitizer lets `data-*` through, so page content could plant a unit.
- The frame's policy can take `style-src 'self'` and `img-src` without opening what ADR 0020
  closed: its script source stays `'self'`, and no markup sink is allowed in the frame.
- Harness instruction files stay at their word count or below; `AGENTS.md` has four words left.

## Contract

The namespace after this plan, behind the `sdk` selection, the same in the three servers.

| Endpoint | Request | Response | Errors |
| --- | --- | --- | --- |
| `GET /api/sdk/v1/config` | the key header; `Origin` | `{ enabled: boolean }` (the switch and the key's) | 403, 429 |
| `POST /api/sdk/v1/telemetry` (frame only) | the key header; `{ events: object[] }`, 1 to 100 | 204 | validation, 403, 413, 429 |

Beside them, outside the OpenAPI document: `GET /api/sdk/dist/v<major>/<file>` now serves
`.css` too, and the frame document's policy gains `style-src 'self'` and `img-src 'self'` plus
`SDK_IMG_ORIGINS`. A body under the namespace is at most 64 KB, read after the key.

## Risks

- A full-viewport frame makes clickjacking easy: a host hides the dialog and collects clicks —
  the guide says an action the server counts in a modal needs the view helper's check first;
  S3 line 10 measures it; the weighing stays the product's.
- `emit` lets a module send anything to the page, where ADR 0020 F3 let only fixed reports
  cross — the rule (nothing the server counts, no token, no server text) moves to the guide and
  the security review, which a module's frame half already asks for.
- The modal rests on behaviour no earlier spike measured — S3 before K2; a refuted line changes
  the ADR before code.
- Four implementers edit one worktree at once — disjoint directories, the SDK ported back in
  one pass, each server's project generated first.
- The three servers drift apart — one brief with fixed names, the same tests in each (V07).
- `handler.ts` of the Worker is shared and its header step changes — the smallest split, every
  test that covers it, the security pass of C8.
- The selection's marker lines can change a tree that has no SDK — V08 compares.
- The reshape reverses parts of an ADR accepted the same day — ADR 0021 names each, and ADR
  0020 keeps its measured spike facts.
